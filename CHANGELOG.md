### Время старта по замерам Moon Core (2026-10-06)
- **Интеграция с Moon Core** (`launcher/moonperf.py`): расширение Moon Core изнутри VS Code
  пишет, сколько стоила загрузка и `activate()` каждого расширения при каждом запуске
  (`%APPDATA%\Code\User\globalStorage\moonlivedt.moon-core\mooncore-perf.json`, поле
  `export`, схема `moon-core/perf@1`; учитываются Insiders и `VSCODE_PORTABLE`).
- Карточка стека: «старт 1,8 с» рядом с размером на диске, в подсказке — откуда число и что
  это верхняя оценка (часть активаций идёт параллельно).
- Панель экономии: «старт быстрее на ~X с» для выключаемых расширений.
- «Замерить расширения»: стеки по времени старта и расширения, которые включаются при каждом
  запуске (`*`, `onStartupFinished`) и стоят от 0,5 с.
- CLI: `--startup-costs` (с `--json`), в `--stack-sizes` — колонка старта.
- Файл пишет другая программа, поэтому он читается как недоверенный: до 4 МБ, строгая схема,
  id по белому списку, числа 0..600000 мс, `samples: true` числом не считается. Нет файла —
  ничего не меняется.
- Тесты `tests/test_moonperf.py`, включая контракт: `tests/data/mooncore-perf.sample.json`
  сгенерирован кодом самого Moon Core.

### Совместимость расширений (2026-10-01)
- **Проверка перед запуском**: включаемые расширения проверяются на версию VS Code
  (`engines.vscode` — по тем же правилам, что у самого редактора), сборку под
  другую ОС, отсутствующие или выключенные зависимости (встроенные расширения
  VS Code учитываются), известные конфликты (Vim + Neovim, несколько серверов
  Python/PHP/Lua, Vetur + Vue…) и устаревшие расширения. Правила — в
  `data/conflicts.json`, логика — `launcher/compat.py`.
- Настройка «Несовместимые расширения» (Настройки → Запуск VS Code):
  **Спрашивать** — окно со списком и выбором «Выключить и запустить / Запустить
  как есть / Отмена» и галочкой «Больше не предупреждать»; **Выключать сами** —
  проблемные выключаются только на этот запуск; **Не проверять**. Кнопка
  «Вернуть скрытые предупреждения».
- Плитка «Совместимость расширений» в «Обслуживании» — отчёт по всем
  установленным. CLI: `--compat-report`, `--compat warn|auto|off`; трей и CLI
  сообщают о проблемах в итоговом сообщении.

  PATH»; длина PATH; место на дисках; длинные пути; прокси. Из отчёта — кнопки

- **Уборка VS Code** находит больше: кэш IntelliSense C/C++ (ipch и базы обзора —

  VS Code, Service Worker-кэши. Отдельно и по умолчанию не отмечено: данные
  удалённых расширений, проекты, не открывавшиеся 90+ дней, локальная история
  удалённых файлов. Колонка «Изменено», кнопки «Только безопасное» / «Отметить
  всё», предупреждение об удалении мимо Корзины для больших объёмов. CLI
  `--cleanup --yes` убирает только безопасное, `--all` — всё.
- Исправлено: кэш CachedData текущей версии мог попасть в уборку, если рядом
  лежала папка прошлой версии VS Code (бралась первая найденная).

### Исправлено (аудит 2026-10-01)
- Повторное нажатие «Запустить», пока лаунчер ждёт закрытия VS Code, запускало
  редактор дважды.
- После ответа «Открыть без папки» проверки проекта смотрели в несуществующий путь.
- Трей/CLI с «закрыть VS Code» закрывали редактор принудительно даже при
  включённом «Закрывать мягко» и даже когда он не был запущен; мягкое закрытие,
  не дождавшись, теперь отменяет запуск, а не добивает окно с вопросом
  «сохранить?».
- CLI `--run --preset` с несуществующим пресетом (опечатка, ярлык удалённого
  пресета) открывал VS Code с одним ядром — теперь ошибка; несуществующая
  папка из `--folder` больше не передаётся VS Code.
- Удалённые в VS Code расширения (помечены в `.obsolete`) больше не считаются
  установленными.
- Путь к самому `Code.exe` (портативная сборка) теперь запускается напрямую, а
  не через cmd.
- «Показать команду»: путь с завершающим `\` (`D:\`) ломал кавычки.
- Импортированный пресет с `"kill": "false"` строкой закрывал VS Code.
- Битые типы внутри списков конфига (`recent_folders: [5]`) роняли окно;
  неизвестные значения темы/режимов сбрасываются на умолчания.
- `.bak` конфига больше не затирается копией испорченного файла.

### Безопасность
- Запасной запуск через `cmd /c` (когда нет Code.exe): каждый аргумент в
  кавычках, `" % !` отвергаются — путь вида `D:\a&calc` больше не выполняет
  вторую команду.
- Ярлык `.cmd` пресета: перевод строки в имени не начинает новую команду, `%`
  экранируется.
- Обновление: exe и `.sha256` берутся только по https с GitHub; без контрольной
  суммы обновление не ставится; тег релиза очищается перед попаданием в имя
  файла и `.bat`; загрузка ограничена 300 МБ; `.bat`-своп экранирует `%` и
  ждёт не дольше ~2 минут.
- Полное удаление с правами администратора больше не использует
  `Remove-Item -Recurse` (в PowerShell 5.1 он проходит по junction-ссылкам в
  чужие папки) — `Directory.Delete`/`rmdir /s`.
- Запись пользовательского PATH отказывается, если новое значение теряет все
  рабочие записи (сбой чтения реестра превращал «дописать каталог» в PATH из
  одной записи); прежние значения пишутся в `path_history.txt`.
- Автопочинка, включающая IntelliSense cpptools, делает копию общего
  `settings.json` VS Code перед правкой.

### Добавлено
- **Умная починка PATH** (Обслуживание → «Починить PATH», CLI `--path-doctor`,
  откат `--path-undo`). Смотрит на системный и пользовательский PATH вместе, как
  Windows: мусор (пустые сегменты, кавычки, дубли, пользовательская копия
  системной записи, мёртвые каталоги, незаданные %VAR%, файл вместо каталога;
  отключённый диск не считается мёртвым) и главное — затенение: заглушка
  Microsoft Store вместо Python, каталог компилятора (MSYS2/MinGW) раньше ваших
  python/cmake/git, каталоги раньше System32 с подменой find/sort, несколько GCC,
  java не из JAVA_HOME, свежая версия за старой, длинный PATH (сжатие через
  %LOCALAPPDATA%…). Каждое исправление — отдельная галочка; предпросмотр
  симулирует новый PATH и показывает, какая команда начнёт запускать другой файл
  и что пропадёт. Бэкап обеих веток, один запрос UAC, откат из меню.
- Описания расширений на английском (plugin_descriptions.en.json).
- **C++-центр** (кнопка «C++…»): установка, проверка и настройка C/C++ в одном окне.
  - Установка по ролям: компилятор (MinGW, MSYS2, MSVC Build Tools или уже
    установленный), сборка, подсказки кода, отладка, анализ и пакеты, библиотеки
    MSYS2, настройка VS Code. У каждого пункта — за что он отвечает и статус.
    Готовые наборы, сводка «сколько / сколько весит / нужен ли админ», установка
    одной кнопкой с прогрессом по шагам. Зависимости подтягиваются сами.
  - Доктор C++: все компиляторы, смесь тулчейнов в PATH, чужая libstdc++, gdb не
    от того GCC, устаревшие Clang/clangd/CMake, Clang без MSVC; пробная сборка
    C++20 (компиляция, линковка, запуск, отладчик); кнопки исправления.
  - Порядок в PATH: основной GCC вперёд, остальные в конец или прочь, с
    предпросмотром, списком пропадающих инструментов и бэкапом.
  - Настройка проекта: tasks/launch/c_cpp_properties или .clangd, CMakePresets,
    .clang-format/.clang-tidy под выбранный компилятор; шаблоны новых проектов
    (один файл, олимпиада, CMake, CMake + vcpkg).
- Наборы C++ в каталоге тулчейнов: MSYS2 (с шагом pacman), LLVM, MSVC Build Tools
  (с `--override` для нагрузки VCTools), cppcheck, ccache, Doxygen, Conan, Meson;
  установка vcpkg.
- Стек C++ разбит на части: база, IntelliSense cpptools, IntelliSense clangd,
  CMake, Makefile, CodeLLDB, дополнительно. Новые расширения: clangd,
  better-cpp-syntax, Doxygen-комментарии, Meson, тесты Catch2/GoogleTest,

  `--install-vcpkg`.
- Талисман из cpp-docs-panel в состояниях C++-центра.
- Отчёт доктора C++ (проблемы, шаги пробной сборки, подсказки по проекту) —
  на языке интерфейса, в том числе по-английски.

- **Удалить полностью** («Языки» → меню «···» у пакета; для C/C++ — кнопка
  «Удалить…» на карточке): winget uninstall, затем папка пакета целиком и записи
  PATH, которые на неё указывали. Перед удалением показывается список папок и
  запрос подтверждения (по умолчанию «Отмена»); права администратора

  или «Подключить Python X.Y», если он уже стоит: папка Python дописывается в
  конец PATH, команда `python` не меняется. Проверка из собранного exe больше не
  подсовывает дочерним процессам свою python3.dll.
- `scripts\Диагностика.bat`: отчёт об окружении C/C++ и VS Code в текстовый файл
  (ничего не меняет) — для разбора проблем на чужом компьютере.

- **Проверка настроек проекта** (вкладка «Проект» и перед запуском VS Code):
  находит удалённый компилятор или отладчик в tasks/launch.json, gdb в папке с

- «Отчёт для поддержки» в «Обслуживании»: версия, выбор, PATH, доктор C++, проект
  и журнал одним текстовым файлом.
- Непойманная ошибка в обработчике показывается окном (раньше — только в журнале),
  сбой записи настроек не обрывает действие.

  итогом; строки журнала со временем; диагностика не портит русские пути.

- **C++: сборка в папке с русскими буквами.** Новые MSYS2 (ld) падали на полном
  пути («cannot open output file C:\\Users\\: Illegal byte sequence»). Задачи теперь
  передают компилятору относительные пути; старые настройки находит и чинит
  проверка проекта; доктор C++ проверяет сборку в такой папке.
- Проверки из собранного exe не подсовывают дочерним процессам его папку в PATH
  (lldb находил там python3.dll без стандартной библиотеки).

- Расширение C/C++ Compile Run добавлено в стек «Code Runner»; в папке с русскими
  буквами проверка проекта предупреждает, что оно собирает с полным путём.

- **Автопочинка перед запуском** (Настройки → «Исправлять проблемы перед запуском
  автоматически», включено по умолчанию): устаревшие настройки проекта
  пересоздаются, нужные стеки включаются, сборщики с полным путём (C/C++ Compile
  Run) в папке с русскими буквами выключаются на этот запуск — в окне, трее и CLI.
  Что сделано, показывает одно сообщение; выключено — лаунчер спрашивает.

### Изменено
- Авто-набор папки выставляет ровно запомненные стеки: лишние от прошлого проекта
  выключаются, а не копятся.
- Отмеченный чекбокс показывает галочку, а не просто залитый квадрат.
- «Навести порядок в PATH» (C++) ставит основной GCC только перед конкурентом, а
  не в начало PATH: каталог MSYS2 с собственным python больше не перекрывает
  установленный Python.
- В отчёте окружения две кнопки «Почистить PATH» заменены одной «Починить PATH…».
- В «Языки и инструменты» C/C++ — одна карточка, ведущая в C++-центр.
- Конфиг v5: выбор `cpp` в пресетах, последнем выборе и памяти папок
  раскрывается в части стека (всё, что было, кроме clangd).
- Проект без компилятора больше не получает навязчивого WinLibs, если стоит
  MSYS2 или MSVC.

### Исправлено
- **Enter больше не запускает VS Code из полей ввода и с кнопок.** Enter после
  набора пути, в поиске стеков или на «Обзор…» закрывал и перезапускал редактор;
  подтверждение принудительного закрытия по умолчанию стояло на «Да». Теперь
  Enter запускает только из самого окна, на кнопке — нажимает её, а в запросе
  по умолчанию «Нет». Esc в поиске сначала очищает поиск.
- **Галочки стеков не переключаются от случайного касания.** Карточки, плитки и
  переключатели-пилюли срабатывали уже на нажатие мыши; теперь — как кнопки, на
  отпускание внутри карточки.
- **Колесо мыши не меняет выпадающие списки.** Прокрутка списка расширений стека
  молча ставила расширениям «всегда вкл / всегда выкл», после чего галочка стека
  «не работала»; то же с пресетом и списками C++-центра.
- Авто-набор папки не включается заново при каждой потере фокуса полем «Папка»:
  снятые руками галочки больше не возвращаются сами.
- «Включить все / минимум» и раскладка карточек работают, когда открыта другая
  страница или окно свёрнуто в трей.
- **Запуск при уже открытом VS Code.** Работающий редактор не применяет новые
  `--disable-extension`; лаунчер раньше молча писал «выключено N расширений».
  Теперь спрашивает: закрыть и запустить, открыть как есть или отменить; трей и
  CLI сообщают об этом в ответе.
- После принудительного закрытия запуск ждёт настоящего выхода процессов, а не
  фиксированные 1,8 с (окно могло не открыться вовсе); трей и CLI тоже ждут.
- Новый VS Code запускается с чистым окружением: лаунчер, открытый из терминала
  или расширения VS Code, передавал `ELECTRON_RUN_AS_NODE` и `VSCODE_*`.
- Трей запускает пресеты с актуальным путём к VS Code и картой расширений (после
  «Установка VS Code» и мастера раскладки).
- Смена языка не роняет приложение, если в этот момент идёт фоновая проверка, и
  возвращает на ту же страницу; во время установки C++ язык не меняется.
- **C++: проверка перед запуском.** Если проект настроен на отладчик или движок
  (launch.json: cppdbg/lldb, CMake Tools, clangd), а его стек выключен, либо
  выбраны стеки C/C++ без движка подсказок — лаунчер предлагает включить нужное.
- **C++: отладка в папке с русскими буквами в пути.** gdb под cppdbg такой путь не
  открывает («No such file or directory»), F5 не работал. Для таких папок отладка
  настраивается через CodeLLDB; добавлена задача «C++: собрать и запустить» —
  запуск без отладчика.
- **C++: задачи и отладка получают каталог компилятора в PATH.** g++ из MSYS2,
  вызванный по полному пути, молча завершался с кодом 1, а собранная программа
  могла взять чужую libstdc++-6.dll (0xC0000139).
- C++-центр: «Проверить заново» и возврат после установки не стирают отмеченное;
  вкладка «Проект» не сбрасывает выбранную систему сборки.
- Удаление пресета спрашивает подтверждение.
- `scripts\Запустить.bat` и `scripts\Собрать_exe.bat` сами находят Python 3.12+ с
  PyQt6 (раньше был зашит 3.14 — на другом компьютере запуск молча не работал),
  пишут понятную ошибку, если его нет; сборка больше не сообщает «Готово» после
  неудачи. Файлы переведены на CRLF и UTF-8 с `chcp 65001`.

## [1.5.0] — 2026-09-29

### Добавлено
- **Память по стекам.** «Замерить расширения» обходит дерево процессов VS Code
  и относит каждый процесс к расширению по пути в командной строке: видно,
  сколько держит SonarLint, Pylance, cpptools и т.д. В CLI — тот же разбор в
  `--measure-extensions`.
- **Уборка** (кнопка «Уборка…», CLI `--cleanup [--yes]`): копии установщиков
  расширений, данные удалённых проектов, кэши движка, старые логи и версии
  расширений. Предпросмотр с галочками, удаление в Корзину, только при закрытом
  VS Code.
- Метка **«стартует сразу»** в «Подробнее» у расширений с активацией `*` или
  `onStartupFinished`.
- Новые стеки: **Орфография**, **Оформление**, **Code Runner** (вынесены из
  ядра), **GitLens / GitHub** (отделён от лёгкого Git), **SQLite / CSV**
  (отделён от SQL Server), **Azure AI / MCP** (отделён от Azure).
- Автоопределение: `.db/.sqlite/.csv` предлагают SQLite, Markdown — орфографию.
- Рекомендованные настройки против фоновой нагрузки (`always_on`) и лимиты
  памяти для C++ и Java; в предпросмотре только недостающие ключи.

### Изменено
- Живой замер памяти учитывает процессы языковых серверов (`cpptools.exe`,
  `java.exe` и т.п.), а не только `Code.exe`. Метка метрики новая
  (`private-bytes-tree`): прежние замеры и базлайн не смешиваются с новыми и
  наберутся заново.
- Конфиг v4: пресеты, последний выбор и память папок дописываются
  отделившимися стеками и «Оформлением», чтобы включать то же, что раньше.
- Qpack, метрики кода и подсветка тегов переехали из ядра в Web.

### Исправлено
- **SonarLint не выключался никогда.** `extensionPack` считался жёсткой
  зависимостью, а набор `seyyedkhandon.qpack` из ядра содержит SonarLint — его
  JVM (сотни МБ) оставалась включённой при любом выборе. Теперь зависимостью
  считается только `extensionDependencies`.
- Автонастройка отказывалась работать с `settings.json` с комментариями — то
  есть почти у всех. Теперь ключи вставляются текстом с сохранением комментариев.
- Разбор JSONC вырезал `//` внутри строк (`cscript //Nologo` в настройках Code
  Runner) и ломал файл.
- GUI-тесты перезаписывали настоящий `launcher_config.json` тестовым; теперь
  конфиг в тестах изолирован.
- Уборка считала «удалёнными» проекты на отключённом диске (флешка, сетевой
  диск) и предлагала выбросить их данные. Теперь такие проекты не трогаются.

## [1.4.0] — 2026-09-08

### Добавлено
- **Значок в трее**: правый клик — список пресетов, выбрал и VS Code открылся
  нужным набором, без открытия окна. Опция «крестик сворачивает в трей».
- **Одноэкземплярность**: второй запуск будит уже открытое окно (`QLocalServer`),
  а не поднимает второе, спорящее за тот же конфиг.
- **Реальный вес стека на карточке** — размер установленных расширений стека на
  диске (`тяжёлый / 865 МБ`), считается в фоне и кэшируется.
- **Калибровка экономии по собственным замерам**: если два прошлых запуска
  отличались одним стеком, разница их footprint'ов и есть цена этого стека на
  этой машине. Берётся медиана, чтобы один шумный замер не задавал число;
  подсказка честно говорит, сколько стеков посчитано по замерам, а сколько по
  таблице нагрузки.
- **«Замерить расширения»** (`code --status`, в CLI `--measure-extensions`):
  сколько памяти держит хост расширений с языковыми серверами, а сколько — сам
  редактор. Не оценка, а ответ самого VS Code.
- **Перетаскивание** папки или `.code-workspace` в окно и кнопка «Рабочая
  область…» — многопапочный проект наконец можно выбрать.
- **Список личных исключений** по расширениям в одном месте, со снятием.
- CLI: `--version`, `--stack-sizes`, `--measure-extensions`.
- Конфиг переживает больше: значения известных ключей проверяются по типу
  (битое сбрасывается поодиночке, а не теряется весь файл), нечитаемый конфиг
  откладывается рядом как `*.corrupt-<время>.json`, а если папка рядом с exe
  недоступна на запись — конфиг и лог уезжают в `%LOCALAPPDATA%\VSCodeLauncher`
  с одноразовым переносом старого файла.

### Изменено
- Замер памяти — **нативный** (Win32 `CreateToolhelp32Snapshot` +
  `GetProcessMemoryInfo`) вместо запуска `powershell.exe`: миллисекунды вместо
  1-2 секунд на каждое открытие окна и после каждого запуска редактора.
  Метрика — приватная память (private commit), общие страницы движка больше не
  считаются у каждого процесса заново. Старые замеры помечены прежней меткой
  метрики и не смешиваются с новыми.
- Смена языка больше не теряет несохранённое: галочки, папка, поиск, фильтр и
  прокрутка переезжают в пересобранное окно.
- Запуск редактора у окна, тихого CLI и трея идёт одним путём
  (`quicklaunch.plan_launch`) — разойтись в поведении они больше не могут.

### Исправлено
- `code --status` не находил хост расширений в нынешних версиях VS Code (процесс
  называется `extension-host`, а не `extensionHost`) — разбор всегда показывал
  «расширения: 0 МБ», а всю память относил к редактору.
- Обрезался текст на карточках стека при первом запуске: размеры расширений
  приходят из фона и удлиняют бейдж нагрузки, а сетка карточек не
  пересчитывалась до первого изменения размера окна.
- В EN-режиме больше сотни строк интерфейса оставались русскими: недостающие
  переводы добавлены, забытые `_()` расставлены, а два теста теперь не дают
  этому повториться. Кнопка «Языки и инструменты» в EN показывала
  «Languages _tools…» — Qt съедал `&` как мнемонику.
- Личные исключения по расширениям не работали в CLI, если были записаны с
  заглавными буквами (окно приводило id к нижнему регистру, CLI — нет).

## [1.3.0] — 2026-09-03

### Добавлено
- **Чистка PATH** прямо из лаунчера: удаление дубликатов и мёртвых записей из
  пользовательского (`--clean-path`) и системного (`--clean-path --machine`,
  через UAC) PATH. Бэкап в файл перед изменением; резервные каталоги тулчейнов
  (`go\bin`, `.dotnet\tools`, а также `path_hints` из каталога) не удаляются.
- **`--fix-java-home`** и кнопка «Исправить JAVA_HOME»: находит установленный
  JDK, прописывает `JAVA_HOME` и, если нужно, добавляет его `bin` в PATH. После
  установки JDK переменная выставляется автоматически.
- **`verify_cmd`** в каталоге тулчейнов: пакет считается установленным, только
  если команда-подтверждение реально отвечает (например, `.NET` — по
  `dotnet --list-sdks`, а не по наличию мультиплексора рантайма).
- Новые тулчейны: **Dart, Julia, Swift** (с автоопределением по файлам проекта),
  Java обновлена до **Temurin 25 (LTS)**.
- Настройка VS Code для **Python** (`python.defaultInterpreterPath`), не только
  для C/C++.
- Экспорт профиля в `.code-profile`, самообновление exe, оверлей раскладки
  клавиатуры (из предыдущей итерации, ещё не в релизе).
- Английские переводы для новых строк интерфейса (доктор, чистка PATH,
  JAVA_HOME, обновления).

### Изменено
- Доктор окружения показывает здоровье PATH **раздельно** для пользовательской и
  системной веток (системная правится только с правами администратора).
- Определение версии инструмента учитывает код возврата (у `go`/`dotnet` больше
  не показывается текст ошибки вместо версии).
- Для Clang выставляется корректный режим IntelliSense (`windows-clang-x64`).

### Исправлено
- Ложное «установлено» для `.NET`, когда в системе есть только рантайм без SDK.
